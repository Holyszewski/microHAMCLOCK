## Project

**microHAMCLOCK** (until 0.8.0 called HamClock) is a small ham radio clock for the **Heltec WiFi LoRa 32 V3** (ESP32-S3, SSD1306 128×64 OLED over I2C). It shows UTC, solar and propagation data, and live PSKReporter spots of "who heard me" as a list and on a world map. The firmware is made of these parts, with no external libraries:
- `src/main.cpp`,
- the localization module `src/i18n.*`, with catalogs in `src/lang/`,
- the time zone table `src/tz.*`,
- the Game of Life screen saver `src/life.*`,
- the generated map bitmap `src/maps.h`. The display driver, font and button code were taken from the sibling project `../Game of Life` (the maintainer's own).

**Language:** the repository is **English**: code comments, tool messages, `README.md`, the full manual `docs/manual.md`, `CHANGELOG.md`, this file and commit messages (from 0.6.0 on; older history stays Czech). Czech exists only as a translation catalog (`src/lang/cs.inc`). The product targets hams worldwide:
- the OLED and the setup web page are localized, English by default, with Czech and German also available,
- the serial console is **English only** (the maintainer's decision) and is not translated, so console strings are plain literals in the code,
- OLED texts must be ASCII (the font has no accents),
- the web page is UTF-8.

**Name (decided after 0.8.0):** **microHAMCLOCK**, written like that in prose; `microhamclock` in file names, the hostname and the MQTT client id; `MICROHAMCLOCK-xxxx` for the hotspot. The boot screen draws MICRO in the normal size (uppercase, the maintainer's choice) on the baseline of the big HAMCLOCK, 126 px of 128. The reference to HamClock by Elwood Downey, WB0OEW (SK January 2026; its Clear Sky server is off, the community continues it as OpenHamClock) is intentional; README's "About the name" says the project is not affiliated with HamClock, the Clear Sky Institute or microHAM s.r.o. The NVS namespace is `microhamclock` too; settings from the old namespace are not migrated, boards set up before the rename must be set up again. **The firmware must not contain the standalone word "hamclock" in any form** (strings, identifiers, comments, not even to migrate old settings): no part of it may suggest it has anything to do with the original (the maintainer's rule). The boot screen therefore splits one "MICROHAMCLOCK" string. The reference stays in README's "About the name" and in the history.

**Docs:** `README.md` is the GitHub landing page, short: features, screens (`docs/img/`, regenerated by `python tools/readme_screens.py`, a Python copy of the renderers with example data, so update it when a screen layout changes), quick start, controls, data credits, license. It must keep the "Made with AI assistance" section (the maintainer's wish). Details go to `docs/manual.md`, which must stay in sync with the firmware. Relative links to GitHub pages need the right depth: `../../releases/latest` from README, `../../../releases/latest` from `docs/`.

## Versioning

The repo is on GitHub (remote `origin`). Push only `main` and release tags by name (`git push origin vX.Y.Z`), never `git push --tags` or `--mirror`. Versions are `0.x.y` while the project is unfinished: bump `x` for a feature and `y` for a fix. **The number changes only at a release, and only when the maintainer says so.** The project switched to this scheme after 0.5.1; before that every change was a release.

- **Between releases (every commit):**
  - write a normal English commit message, without the `microHAMCLOCK 0.x.y:` prefix,
  - add the change to the `## Unreleased` section at the top of `CHANGELOG.md` (create it if missing),
  - don't tag.
- **Version string:** `tools/version.py` (a PlatformIO `pre:` script) writes the gitignored `src/fw_version.h` before each build from `git describe`, e.g. `0.5.1-3-g1a2b3c4` (3 commits after v0.5.1), plus `-dirty` with uncommitted changes. `status`, the serial banner and the web page show it in full. The OLED shows `FW_VERSION_OLED` as `v0.5.1+3` (no hash; `+` alone for uncommitted changes on a release), with a lowercase `v` glyph in the font. On the status screen it sits bottom right, because next to the callsign in the header it wouldn't fit in 21 chars. Never hardcode the number in the source.
- **Release:**
  1. pick the number from what's in `Unreleased` (any feature → `x+1`, `y=0`; only fixes → `y+1`),
  2. rename the section to `## X.Y.Z – date`,
  3. `python tools/release.py build X.Y.Z`: the release build (`MICROHAMCLOCK_RELEASE=X.Y.Z python -m platformio run`; `version.py` refuses a number that doesn't match the first CHANGELOG heading) and both distribution binaries in `firmware/` (see Distribution),
  4. make one commit `microHAMCLOCK X.Y.Z: …` (`HamClock X.Y.Z` up to 0.8.0) and tag `vX.Y.Z`. A build from the tag then gives exactly `X.Y.Z`,
  5. push the commit and the tag (`git push origin main vX.Y.Z`),
  6. `python tools/release.py publish X.Y.Z`: creates the GitHub Release for the tag with `gh` (the CHANGELOG section as notes, both binaries attached, marked latest; run again it updates the release), then publish the installer site.

Commits are made under the identity already set in git config.

## Build / flash

PlatformIO only, run as `python -m platformio …` when `pio` isn't on PATH. The stock `espressif32` platform uses Arduino core 2.x.
```
pio run                              # build
pio run -t upload --upload-port COMx # flash (the board's USB bridge is a CP210x)
pio device monitor                   # serial console, 115200
```

Check `pio device list` before flashing when more boards are attached.

There are no tests. Verify a change by building, flashing and reading the serial log (`WiFi: connected`, `MQTT: subscribing to …`, `Spot: …`, `Propagation: …`). `blink` switches to the solar screen and fakes new propagation data a second later, so the data blink can be watched (or caught with `snapshot`). The `status` command prints the full state; the old Czech commands `stav` and `snimek` still work as aliases. `python tools/snapshot.py COMx out.png` sends `snapshot` and saves the current screen as a PNG, so layouts can be checked without a photo. It opens the port with DTR/RTS low so the board doesn't reset, and it can't run while `pio device monitor` holds the port.

## Distribution

Binaries are **not in git** (`firmware/` and `site/` are gitignored, the maintainer's decision). They are made only at a release, after the `MICROHAMCLOCK_RELEASE` build; `tools/release.py build` does all of this:
```
pio pkg exec -p tool-esptoolpy -- esptool.py --chip esp32s3 merge_bin -o firmware/heltec_v3_microhamclock-merged.bin --flash_mode dio --flash_freq 80m --flash_size 8MB 0x0 .pio/build/heltec_v3/bootloader.bin 0x8000 .pio/build/heltec_v3/partitions.bin 0xe000 %USERPROFILE%/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin 0x10000 .pio/build/heltec_v3/firmware.bin
```
Also copy `.pio/build/heltec_v3/firmware.bin` to `firmware/heltec_v3_microhamclock.bin`. Both go to the GitHub Release (`tools/release.py publish`, which refuses binaries that aren't a release build of that number and a tag that isn't on `origin`). **The asset names never contain the version**, so `…/releases/latest/download/heltec_v3_microhamclock-merged.bin` always serves the newest release; README and the manual link there, so keep the names. Those links work for everyone only once the repository is public. Users flash the merged file at `0x0` with any ESP32-S3 flasher (esptool-js, esptool, the MeshCore flasher with a custom file), or with the web installer. **An update keeps the settings** because of the partition table `partitions.csv` (`board_build.partitions`, since 0.10.0, the maintainer's decision): Arduino's `default_8MB.csv` with NVS moved from 0x9000 to 0x7E0000 (64 KB, taken from spiffs). The merged file runs from 0x0 to the end of the app and fills gaps with 0xFF, so with NVS at 0x9000 every install erased the settings, whether the installer's erase was ticked or not (`pio run -t upload` writes the parts separately and never had the problem). 0x9000–0xe000 stays unused. `check_nvs()` in `tools/release.py` (also called by `build_site.py`) reads the partition table inside the merged image and refuses it if the image reaches into NVS. Keep NVS behind the app; moving it again would cost every board its settings once, as the move to 0.10.0 did.

**Web installer:** `web/index.html` is a one-click install page using ESP Web Tools (pinned version from unpkg) with `{{VERSION}}` and `{{REPO_URL}}` placeholders. `python tools/build_site.py` assembles `site/`: the page, `manifest.json` (ESP32-S3, the merged file at offset 0, `new_install_prompt_erase`), the merged binary from `firmware/` and `img/demo.png`. `--serve` serves it on localhost, where browsers allow Web Serial, so it can be tested in Chrome before publishing. On GitHub it goes to GitHub Pages; the firmware must be on the same site as the page (CORS), so it can't be loaded from the Release assets. Without Actions the contents of `site/` would be pushed to a `gh-pages` branch by hand (as a single orphan commit, so binaries don't pile up in history).

**Map:** `src/maps.h` is generated, so don't edit it by hand. Regenerate it with `python tools/make_map.py <ne_110m_land.geojson> <ne_10m_admin_0_countries.geojson>` (Natural Earth, public domain, downloaded from github.com/nvkelso/natural-earth-vector). `--preview <dir>` writes PNG previews. The views are defined in `VIEWS` there: WORLD and EUROPE are land masks; CZECHIA, GERMANY, UK and USA are the territory of one country (`ADM0_A3` `CZE`, `DEU`, `GBR`, `USA`), each with the same km per pixel both ways (4.7, 14, 19, 45 km). USA is the contiguous 48 states (Alaska and Hawaii are outside the view); the Germany and UK views are wide because those countries are tall.

## Gotchas

- **No secrets in the source:** Wi-Fi, callsign and locator live only in NVS (namespace `microhamclock`) and are entered with the serial `setup` wizard or the hotspot form. The release binaries are shared, so never hardcode credentials.
- **Time:** SNTP starts after the first Wi-Fi connect (`ntp.ufe.cz`, the Czech national time standard at ÚFE AV ČR, then `tik.cesnet.cz`, then `pool.ntp.org`).
- **Year 2038 (open, postponed on 2026-10-10):** on Arduino core 2.x the toolchain's newlib (gcc 8.4, esp-2021r2) is built with `_WANT_USE_LONG_TIME_T`, so `time_t` is a signed 32-bit type and the system clock wraps to 1901 on 19 January 2038 (clock, date, DST, spot ages, the map terminator, night mode). It can't be changed by a build flag. Our own unix times are `uint32_t` (good until 2106), and `jsonLong()` and the ionosonde time are already 64-bit. The two ways out, both left undecided: move to Arduino core 3.x / IDF 5 (64-bit `time_t`, needs the pioarduino platform and a port of the Wi-Fi and hotspot DHCP code), or stay on 2.x and read the clock as `uint32_t` with our own gmtime and POSIX TZ evaluation instead of `gmtime_r`/`localtime_r`. A `static_assert(sizeof(time_t) >= 8)` will tell when the platform is fixed.
- **Time zones (`src/tz.cpp`):** a hand-written table of about 50 regions, each with an IANA id, a POSIX rule, the standard offset, a city label and the IANA aliases used for browser detection. Fixed offsets `UTC-12`…`UTC+14` are added on top.
  - The maintainer chose this short list over generating the full IANA table from `tzdata`, because 15 KB of flash seemed too much to them. Keep the rules current, for example Mexico and Iran dropped DST, Egypt brought it back, and Kazakhstan moved to +05.
  - Never ask users for POSIX strings: they pick a city.
  - The web form preselects the zone from `Intl…timeZone` while the zone has never been chosen.
  - NVS key `tzid`. The old key `tz`, a POSIX string from 0.1, is removed on save. A board configured before 0.4.0 without `tzid` gets `Europe/Prague`, a new board gets `Etc/UTC`.
- **Plain C++, no auto-prototypes:** every `static` function must be defined before its first use, and the file keeps that order.
- **Hardware specifics:** `Vext` (GPIO36) LOW powers the OLED, OLED reset is GPIO21, and I2C is SDA 17 / SCL 18 at 700 kHz. The PRG button is GPIO0. I2C writes are chunked to 64 bytes.
- **Two tasks:** `netTask` (core 0) does Wi-Fi, NTP, MQTT and HTTPS, and may block. `loop()` (core 1) does the display, button and serial console, and must not block. `spots[]` and `solar` are shared and guarded by `dataLock`. Rendering works on a copy (`takeSnapshot`).
- **Config mode (hotspot):** it is entered only at boot. The trigger is `!configured()`, or the NVS flag `portal`, which the 10 s button hold sets right before `ESP.restart()`. The flag is cleared at boot, so a power cycle always returns to normal mode. In config mode `netTask` is never started. The open AP `MICROHAMCLOCK-xxxx` (`WIFI_AP_STA`, where STA is used only for scanning), the `DNSServer` captive portal and the `WebServer` form all run from `loop()` via `portalService()`. Entering config mode must never erase stored values (the maintainer insisted): the form is prefilled, an empty password keeps the stored one, and leaving without saving (button, `/cancel`, or `PORTAL_IDLE_MIN` of inactivity on a configured board) just restarts. The web page may use diacritics, because it is UTF-8 and not the OLED. Arduino core 2.x does not make the softAP DHCP server offer a DNS server, and without one phones never ask our DNS and never detect the captive portal (confirmed on a real phone: the page didn't pop up). `portalStart()` therefore restarts DHCPS with `OFFER_DNS` and the AP IP as the DNS server. IDF 4.4 has no DHCP option 114 (captive portal URI). The AP IP is deliberately `PORTAL_IP` = 4.3.2.1 and not 192.168.4.1. The serial log showed that an Android phone resolved connectivitycheck.gstatic.com to a private IP and then never sent the HTTP probe, so it showed no sign-in prompt. DNS is a small hand-written UDP responder (`dnsService()`): it answers A queries with the AP IP and returns an empty NOERROR for everything else. Unknown paths go to a `CatchAll` RequestHandler, not `onNotFound`, because the core logs an error for every not-found request. Network scan: in `WIFI_AP_STA` a scan takes about 8 s (measured), but the core's `scanComplete()` returns `WIFI_SCAN_FAILED` after 6 s (300 ms per channel × 20) while the scan goes on and finishes fine, so `scanService()` ignores that and waits up to `SCAN_TIMEOUT_MS` itself; an empty or failed scan is repeated `SCAN_RETRIES` times. The form's script polls `/nets` (JSON) while a scan runs and redraws the list without a reload; `/nets?scan=1` starts a new scan.
- **Wi-Fi failures:** `onWifiDisconnect()` maps the disconnect reason to `wifiFailSeen`; `netTask` copies it to `wifiFail`, which screens show as `S_WIFI_BAD_PASS` or `S_WIFI_NO_AP`, only after Wi-Fi has been down for `WIFI_FAIL_SHOW_MS` (20 s). The first attempt after a restart nearly always fails with reason 2 (AUTH_EXPIRE) and the next one connects, so showing it at once was a false alarm. `WIFI_REASON_ASSOC_LEAVE` is ignored, because our own retry `WiFi.disconnect()` would otherwise overwrite the real reason. Wrong WPA2 passwords usually come as reason 15 (4-way handshake timeout). The core doesn't auto-reconnect after some reasons (`AUTH_FAIL` isn't in `_isReconnectableReason`), so `netTask` calls `WiFi.begin()` again every `WIFI_RETRY_MS`.
- **Screen saver (`saverService`/`showFrame` in main.cpp):**
  - `lastActivity` is updated by button activity and by `spotWakeAt`. The net task sets `spotWakeAt` for spots younger than `SPOT_WAKE_MAX_AGE_MIN`, and it counts only when `wakeOnSpot` is on and either it is day or `nightMode == NM_SPOTS` (the default `nmode` since after 0.6.0, the maintainer's wish; before it was `NM_BUTTON`).
  - `asleep` is true after `saverMin` minutes without activity, or always at night in `NM_DARK`. It is never true in the portal, during the wizard, or while the button is held past `CONFIG_HINT_MS`.
  - The modes are `SV_OFF` (panel off via `oledPower`), `SV_LIFE` (`life.cpp`, no text by design, so nothing to translate or burn in) and `SV_DIM` (normal render, dimmed, `fbShift` by 0–2 px every minute).
  - The first press while asleep sets `wakeSwallow`, so it only wakes the display. `BTN_CONFIG` always works.
  - A spot that wakes the display switches to `S_PSK_LIST`.
  - Since 0.5.0, optional `ledOnSpotWake` (NVS `svled`, default true since after 0.6.0; before it was false) flashes the built-in LED (GPIO35, active HIGH) for `SPOT_LED_MS` (500 ms), only on an actual asleep-to-awake transition caused by a spot. It applies to off/life/dim savers, respects night restrictions, and does not flash for button wakes or spots received while already awake. The web form and serial wizard both expose this option; `status` prints it. On the web it is indented under "a new spot wakes the display" and greyed out (CSS class `off`, not `disabled`, so the stored value is still submitted) while that is unchecked. `saverService()` switches the LED off without blocking.
  - Optional `lifeOff` (NVS `lfoff`, default false) with `lifeDays` (NVS `lfdays`, 1–`MAX_LIFE_DAYS` = 30, default 2): after that many days of the Life saver `showFrame` turns the panel off, but the saver mode stays `SV_LIFE` and waking works as usual; the count restarts whenever Life starts again. Web Advanced only (the maintainer's wish), not in the wizard; the days input is greyed out (class `off`) while unticked, and is then not validated. `status` prints it.
  - The console command `saver [off|life|dim]` (`saverCommand`) sets `saverForced` (and `saverForceMode`, -1 = the set mode) so `asleep` is true right away, also with the saver set to never. Settings don't change. Any activity after `saverForcedAt` (button, spot wake, `blink`) or a busy state clears it. `saverModeNow()` gives the effective mode for `showFrame` and the frame timing.
  - All of this was decided by the maintainer one question at a time, so don't change the behaviour without asking.
- **Brightness:** `cfg.bright[BrightMode]` (day, night, dim saver, life saver) holds the raw SSD1306 contrast 0–255, NVS keys `brday`/`brnight`/`brdim`/`brlife`, defaults `CONTRAST_*`. The web shows it as 1–100 % (`contrastToPct`/`pctToContrast`) in a collapsed "Advanced" `<details>`, which opens by itself once any value differs from the default. Moving a slider calls `/bright?v=` and the portal shows that contrast for `BRIGHT_PREVIEW_MS` without saving. Web only, not in the serial wizard; `status` prints it.
- **Battery and power off (POWER section):**
  - VBAT is read on GPIO1 through a 390k/100k divider (`VBAT_DIVIDER` 4.9) that GPIO37 switches on: active LOW on V3/V3.1 (pull-up), active HIGH on V3.2 (transistor). `batteryInit()` reads GPIO37 as an input before driving it (HIGH = V3/V3.1) and then keeps the divider on. NVS `board` (`BoardRev`: auto, V3/V3.1, V3.2; default auto) overrides it, web Advanced at the bottom (the maintainer's wish), not in the wizard. A V3.1 is detected correctly.
  - Without a cell, on USB, a V3.1 reads a steady 3.20 V, so a missing cell looks like a flat one. That's why `BAT_AUTO_OFF` (power off below `BAT_OFF_MV` for `BAT_OFF_COUNT` readings, then timer wakes every `BAT_RECHECK_MIN` until above `BAT_ON_MV`) is prepared but `false` (the maintainer's decision). The battery is not shown on the OLED (no room on the status screen, the maintainer's call); `status` prints it.
  - Power off (`powerOff()`): a long press on the status screen (the maintainer's choice; so the 10 s setup hold doesn't work there) or the console `off`. It shows a message, suspends `netTask`, turns Wi-Fi off, puts the SX1262 to sleep over SPI (its standby would dominate), releases I2C, holds Vext HIGH, the divider off and LoRa NSS/RST HIGH (`gpio_hold_en` + `gpio_deep_sleep_hold_en`), and enters deep sleep with no wake-up source: only RST starts the board (the maintainer's choice, lowest draw). `releasePinHolds()` at the start of `setup()` undoes the holds. The deep sleep current hasn't been measured properly yet.
- **Factory reset (`factoryReset()`):** the red button at the bottom of web Advanced (`formaction=/factory`, `formnovalidate`, a JS `confirm()`; `handleFactory` replies, then the delayed restart erases first via `factoryPending`) and the console `factory`, confirmed by `yes` on the next line (`factoryAsked`). It suspends `netTask`, turns Wi-Fi off and calls `nvs_flash_erase()`, which wipes the whole NVS partition, including the network the Wi-Fi driver stores there, then restarts into setup mode. Not in the wizard or the USB setup page.
- **Quiet log:** while the wizard runs, `quietLog` silences the net task's serial prints so they don't interleave with what the user is typing.
- **Wizard prompts end with a newline:** the ESP Web Tools console shows a line only after its newline, so a prompt left open stayed invisible and users answered the previous question (a Wi-Fi password once ended up as the callsign). The answer goes on the next line.
- **USB setup (web installer):** the installer page (`web/index.html`) sets the basics over Web Serial. A line starting with STX (0x02) is a command from the page and is never echoed (it may carry the password); replies are single lines `HC <type> <json>`: `info` (version, settings without the password, languages, time zones), `scan` (Wi-Fi networks; the first scan after boot may come back empty, the page retries), `save k=v&…` (URL-encoded lang, ssid, pass, open, call, loc, tz; no `pass` keeps the stored one) → `HC ok` and a restart, or `HC error {field, msg}`. `checkBasic()` does the validation for both the hotspot form and this. It works in normal and setup mode. After saving, the page follows the boot log lines `WiFi: connected`, `NTP: time set`, `MQTT: subscribing`, so keep those texts stable (one `WiFi: cannot connect` at boot is normal). It has a Disconnect button and releases the port before Install.

## Localization (src/i18n.*, src/lang/*.inc)

- **Catalogs:** each catalog is a list of `TR(ID, "text")` lines.
  - `lang/en.inc` is the master. The `StrId` enum is generated from it (X-macro) in file order, so new IDs go there first.
  - Other catalogs are `{id, text}` pairs, so their order doesn't matter. A missing entry falls back to English.
  - `build()` fills one table per language at the first `setLanguage()`/`tr()` call, so switching languages is just an index change.
- **ID prefixes:** `S_` is the OLED (ASCII, at most 21 chars per line) and `W_` is the web page (UTF-8, may contain HTML).
- **Placeholders:** a translation must keep the same printf placeholders in the same order, because translated strings are used as `snprintf` formats.
- **Checking:** run `python tools/check_lang.py` after touching a catalog. It reports unknown or duplicate IDs, placeholder mismatches, non-ASCII `S_` texts (all as errors), and missing translations and long OLED lines (as warnings).
- **Adding a language:** add the catalog, `LANG_xx` in `enum Lang` (`i18n.h`), and a row in `LANGS` (`i18n.cpp`). The `static_assert` checks that the counts match.
- **Stored setting:** NVS key `lang` holds the ISO code (`en`, `cs`, `de`), never the enum number. A missing or unknown code means English. The wizard asks for it first. The web form has it as its first field, and changing it reloads the page with `?lang=`, so the form previews in that language before saving.
- **Dates:** formatted by `formatDate()` with the `S_DATE_FORMAT` pattern (`%a %d %b %Y` in English, `%a %d.%m.%Y` in Czech), using the contiguous `S_DOW_*`/`S_MONTH_*` IDs. Numbers always use a decimal point, because the font has no comma.

## Architecture (src/main.cpp)

Sections in file order: SETTINGS, HARDWARE, DISPLAY, FONT, CONFIGURATION, GEOGRAPHY, SHARED DATA, PSKREPORTER (MQTT), PROPAGATION, NETWORK TASK, POWER (battery, power off), SERIAL CONSOLE, SETUP MODE (HOTSPOT), USB SETUP (WEB INSTALLER, plus `serialService`), SCREENS (renderers, contrast, button), then `setup`/`loop`.

- **MQTT:** a hand-written MQTT 3.1.1 client (CONNECT with a clean session and 60 s keepalive, one QoS 0 SUBSCRIBE, PINGREQ every 30 s, reconnect with backoff from 5 s to 120 s, ±10 % jitter). Data downloads (`httpsGet()`) follow the same idea: refresh intervals have ±10 % jitter, and a failed one is retried after 2 min, doubling up to 1 h (`retryDelay()`). Ionosphere every 15 min, solar every 30 min. The topic is `pskr/filter/v2/{band}/{mode}/{sender}/{receiver}/{sloc4}/{rloc4}/{sdxcc}/{rdxcc}`, with `/` in callsigns replaced by `.`. The payload is flat JSON (`rc`, `rl`, `b`, `rp`, `t` …) read by `jsonStr`/`jsonLong`.
- **Spots:** up to `MAX_SPOTS`, deduplicated by receiver call plus band. They expire after `SPOT_WINDOW_MIN`, using the PSKReporter `t` time when NTP is valid and `millis()` otherwise.
- **Callsign variants:** `mqttSubscribe()` sends one SUBSCRIBE with several topics: the call as entered, its base form (`baseCall()`, the longest part between slashes) and the base with each of `CALL_SUFFIXES` (`/P`, `/M`). The SUBACK carries one result per topic.
- **Solar:** fetched within a minute after Wi-Fi comes up (`START_SPREAD_MS`, so boards don't all ask at once), usually before NTP; then `fetchedAt` is 0 and `netTask` fills it in from `fetchedMs` once the clock is set, so the status screen shows a time, not just OK. HTTPS GET (`httpsGet()`, with `setInsecure()` because the data is public) of the hamqsl.com XML, parsed with `String::indexOf`.
- **Ionosonde:** `fetchIono()` downloads KC2G `stations.json` (about 42 KB, about 100 GIRO stations, roughly 40 of them with fresh data; Asia is nearly empty) and walks every record (`parseIonoRecord`). It reads `code`, `name`, `latitude`/`longitude` (strings, longitude 0–360), `fof2`, `mufd` and `time`, which is in UTC and turned into unix time with `daysFromCivil`. By default it takes the nearest station to the locator with a fresh measurement within `IONO_MAX_KM` (1500 km); the previous station stays while it is at most `IONO_STICKY_KM` farther than the nearest, so values don't jump between stations that drop out in turns. NVS key `iono` (Advanced on the web) forces a station code, e.g. `PQ052` (Průhonice); empty means nearest. It runs only with valid time, since freshness can't be judged without it. No suitable station leaves the old data to age out. The status screen shows the station code under the IONO time; `status` and the log show code, name and distance. KC2G `history.json` needs an internal numeric station id, so it isn't used. A measurement older than `IONO_MAX_AGE_MIN` shows as `--`.
- **NVIS:** `nvisBand()` picks the highest band (160/80/60/40/30/20 m, lower band edge) at or below foF2 × (1 − margin). Margin `nvismg` (0–50 %, default 0, the maintainer's choice; the classic FOT would be 15 %) and `nvis60` (default on) are in Advanced on the web. The solar screen shows `NVIS80` centred at x=43 between `K` and `XRAY` (it fits even with `K 9` and `XRAY X10.2`), or `NVIS --`.
- **Data blink:** the net task bumps `propagationSeq` when really new data arrive (N0NBH `<updated>` changed, or a new ionosonde measurement/station). If the solar screen is visible at that moment (not asleep, status, portal or wizard), `render()` inverts it for `DATA_BLINK_MS`.
- **Map:** an equirectangular `MapView` with a 1-bit land mask. The coastline is computed at runtime from the mask. Day land is a checkerboard and night land is outline only, with the terminator taken from `subsolarPoint()`. `MapMode` holds the views (`MAP_OF[]`); the country views CZECHIA, GERMANY, UK and USA come from `MM_CZECHIA` on and are offered only when switched on (`mapEnabled()`, NVS `mapcz`/`mapde`/`mapuk`/`mapus`, all default off, the maintainer's wish so international users don't get Czechia; web Advanced only, not in the wizard; `status` prints them). New views go at the end, `mapmode` is stored as a number. The long press skips switched-off views, and a stored mode that is switched off renders as AUTO. Czechia, Germany and UK are outline only, with no day/night fill (the maintainer's request); the USA keeps the terminator (also the maintainer's request). AUTO picks the first switched-on country whose mask (`inCountry()`, one pixel to spare for coastal stations) holds every spot and the home QTH, otherwise Europe when they're all inside the Europe view, otherwise the world. The corner number counts the spots visible in the current view.
- **Font:** the 5×7 sprite sheets from Game of Life plus `+()<>=`, a lowercase `s`, used only as the seconds unit ("10s", which the maintainer prefers), and a lowercase `v` for the version ("v0.5.1", also the maintainer's wish). `drawText` looks up each char exactly first and falls back to its uppercase form, so draw user data (locator, SSID) through `upperCopy()`. It takes a scale and an `on` flag (black on white for the headers). When adding glyphs, keep every row exactly `chars * 6 - 1` long.
- **Button** (`pollButton`): short press, double and triple click, long press and `BTN_CONFIG`. Since 0.5.0, the long press fires once **while held**, at `LONG_PRESS_MS` (700 ms); release must not fire it again or generate a click. Continuing to hold still fires `BTN_CONFIG` at `CONFIG_HOLD_MS` (10 s). The maintainer explicitly accepts that entering setup also changes map zoom or list sorting along the way. The first press from the saver still only wakes the display, with setup available on the same hold. `buttonHeldMs` drives the on-screen countdown, which starts at `CONFIG_HINT_MS`.
